# Deliver the adversarial-review obligation specification

## Observable behavior

- The generated contract carries one standing bullet stating that an ordinary
  programming change carries an independent adversarial review of the finished
  result beside its anchor, that the worker runs it before reporting done, and
  that this holds unless the dispatch says the main agent runs it. The bullet
  names no transport.
- `choosing-graph` names both routes that discharge the obligation: the worker
  through its own `Agent` tool or `bringing-coworker`, or the main agent
  dispatching it against the committed result. Its Verification requires an
  ordinary programming change to have one, run by either.
- `shipping-task` Task 4 states the obligation for the changes it carries and
  says the brief names the route only when the worker is not running it. Task 6
  discharges it against the confirmed commit or merge reference and dispositions
  what it reports — closed there, or carried into a named follow-up — before the
  task counts as complete. Its Verification requires that.
- `boss-say` Task 7 discharges the same obligation for a batch item, which
  reaches it instead of `shipping-task` Task 6, and its Verification requires
  that. `choosing-graph` names both acceptance points rather than one.
- `dispatching-work` Task 3 leaves the review's default assignment to the
  contract and has the brief say so only when the main agent runs it instead.
- The contract's missing-anchor fallback is its own bullet, outside the
  `herdr-pane` scoping, and names the `awaiting-main-agent` checkpoint as the
  action — executable where no reply can arrive mid-task.
- `dispatching-work` Task 3's Verification scopes its universal to every brief
  statement **about the work**, and states the coordination the dispatch fixed as
  the brief's own element. The allowed-source list still does not name the
  anchor.
- `docs/roles.md` defines the coordination graph alongside the reality anchor —
  the main agent states it before dispatching, a dispatched agent states its own
  for its own task — and `i-am-orchestrator` lists it among the machinery a main
  agent decides.
- `choosing-graph` settles `orchestrator-worker` ahead of the other two: more
  than one app-rooted worker under one coordination loop is that shape whatever
  else runs beside it. The `single-loop`/fan-out tie-break keeps its own
  paragraph and its own scope.
- `shared-resource-coordination.md`'s release rule is titled for both locks it
  releases, and `dispatching-work`'s Wrap-up branch and `plan-mechanics.md`'s
  auto-detach both locate it by that title.
